# Pendulum Studio

교육용 회전 도립 진자 키트로 강화학습을 가르치는 데스크톱 앱. Electron이고, 화면 구성은
KidsBlock(Keyestudio의 Scratch 3 기반 IDE)을 따릅니다.

## 왜 Electron인가

KidsBlock 웹판은 하드웨어에 붙으려면 **KidsBlock Link**라는 별도 로컬 서비스를 깔아야 합니다.
브라우저가 시리얼 포트에 직접 붙지 못해 중간 다리를 두는 구조입니다. Electron은 시리얼을
직접 잡을 수 있어 이 단계가 통째로 없어집니다. 교실에서 설치할 것이 하나 줄어듭니다.

## 실행

```
cd app
npm install
npm start
```

**npm 11 이상에서는 한 단계가 더 필요합니다.** npm 11부터 패키지의 설치 스크립트를 기본으로
막기 때문에 Electron 바이너리(약 110 MB)를 내려받는 `postinstall`이 실행되지 않습니다.
`npm install`이 `install-scripts not yet covered by allowScripts` 경고를 내면:

```
npm install-scripts approve electron
npm rebuild electron
```

`node_modules/electron/dist/electron.exe`가 생겼는지 확인하세요. 압축 해제가 조용히 실패하는
경우가 있는데, 그때는 `%LOCALAPPDATA%\electron\Cache` 안의 zip을 그 폴더에 직접 풀면 됩니다.
`serialport`는 선택 의존성이라 승인하지 않아도 앱은 뜹니다(실제 키트 연결만 비활성).

모델과 정책은 `src/assets` 에 이미 들어 있습니다. 키트나 모델이 바뀌어 다시 만들 때(프로젝트 루트에서):

```
python s2r/train_app_rules.py --plan      # 따라 하기 아홉 칸 정책 학습 (3개씩 동시, 약 15분)
python s2r/export_app.py                  # model.js, policies.js 내보내기 + 검증용 기준 자료
node s2r/check_app_physics.js             # 앱 물리가 파이썬 환경과 같은지
node s2r/check_app_rules.js               # 아홉 칸 정책의 행동
node s2r/check_app_learning.js            # 예시 규칙 고쳐 배우기
```

`app/src/assets/model.js`(동역학 상수)와 `app/src/assets/policies.js`(정책 가중치 + 학습 곡선)가 만들어집니다.
`index.html`이 `src/` 안에 있으므로 **assets도 `src/` 안에** 있어야 합니다. 밖에 두면 스크립트가
404가 나고, `PS.MODEL`이 없어 첫 줄에서 바로 죽습니다.

## 배포 (조원·다른 PC에 나눠 줄 때)

```
npm run dist
```

`app/dist/PendulumStudio-Setup-0.1.0.exe` (약 84 MB)가 만들어집니다. 받는 쪽은 Python도 Node도
설치할 필요가 없습니다. 같이 보낼 안내문은 `app/설치_안내.md` 에 있습니다.

- 아이콘은 `build/icon.ico`. 외부 그림 파일 대신 `build/make_icon.py` 가 크기별로 따로 그립니다
  (큰 그림을 16·24px로 줄이면 막대가 사라져서, 작은 크기는 요소를 단순화해야 합니다).
- NSIS 설정은 `perMachine: false` 입니다. **관리자 권한 없이 내 계정에만 설치**되므로
  학교 PC나 조원 노트북에서 막히지 않습니다. 설치 위치는 `%LOCALAPPDATA%\Programs\Pendulum Studio`.
- **서명하지 않았으므로 SmartScreen 경고가 뜹니다.** 받는 사람은 "추가 정보 → 실행"을 눌러야
  합니다. 없애려면 코드 서명 인증서가 필요합니다(유료).
- 버전을 올리려면 `package.json` 의 `version` 을 고치면 파일 이름도 따라 바뀝니다.
- `author` 가 설치 정보의 게시자 이름으로 들어갑니다. 지금은 `Pendulum Studio` 입니다.

## 블록 코딩

범주 이름·색·순서와 블록 모양(왼쪽 V 홈, 오른쪽 반원, 모자 블록의 원, 육각 판단 블록, 노란 숫자 칸)은 엔트리를 따릅니다.
블록은 DOM 에 중첩해 자리를 잡고, 모양은 자리가 잡힌 뒤 크기를 재서 블록마다 SVG 경로로 그립니다(`blocks.js` 의 `decorate`).

| 범주 | 블록 |
|---|---|
| 시작 | `매 순간 점수 매기기`, `시작하기 버튼을 클릭했을 때` (조립소에 고정된 모자 블록 둘) |
| 흐름 | `만일 < > (이)라면`, `만일 < > (이)라면 … 아니면` |
| 판단 | `( ) < ( )`, `( ) > ( )`, `그리고`, `또는`, `(이)가 아니다` |
| 계산 | `+`, `-`, `x`, `/`, `( ) 의 [제곱 ▾]` |
| 점수 | `점수에 ( ) 만큼 더하기`, `점수에서 ( ) 만큼 빼기` |
| 키트 | 진자 높이·진자 빠르기·팔 빠르기·모터 힘 값 (모두 0~100), 진자 기울기·팔 각도 값 (도), `진자가 똑바로 섰는가?`, `팔이 제자리에 있는가?` |
| 인공지능 | `학습 조건 [세대 ▾] 을(를) ( ) (으)로 바꾸기`, `내 점수 규칙으로 정책 학습하기`, `( ) 초 동안 시험하기` |

- `▶ 시작하기` 를 누르면 `시작하기 버튼을 클릭했을 때` 아래 블록을 위에서부터 실행합니다. 학습 조건은 CEM 의 세대 수·집단 크기·변이 크기에 그대로 연결됩니다.
- **따라 하기**는 고정된 블록에서 고르는 칸만 바꿉니다(아홉 조합, 미리 학습한 정책). **자유롭게 만들기**는 블록을 직접 쌓고 CEM 으로 고쳐 배웁니다.
- **규칙 점검**: 블록을 놓는 순간 똑바로 섰을 때·매달렸을 때·빨리 돌 때의 점수를 견줘, 부호를 반대로 쌓았거나 빨리 돌수록 점수가 높은 규칙을 학습 전에 알려 줍니다.
- 시험하는 동안 점수 블록마다 **지금 받는 점수**가 옆에 뜹니다.
- 실제 키트 시험은 같은 정책이 안전 시험(40칸 중 37칸 이상)을 통과하고 시뮬레이션에서 진자를 세운 뒤에만 됩니다.
- 학습과 시뮬레이션 시험은 화면 주사율에 묶지 않았습니다(창이 가려져도 같은 속도).
- 쌓기 블록을 끌면 엔트리처럼 그 아래에 붙은 블록도 함께 움직입니다. 휴지통이나 블록 꾸러미로 끌면 버립니다.
- 되돌리기 / 다시 실행(위쪽 화살표 버튼, Ctrl+Z / Ctrl+Y), 조립소 확대·축소(왼쪽 아래, 60~200%, 다음에 열 때도 유지).
- 시작하기를 누르면 지금 실행 중인 블록(학습하기 → 시험하기)이 노랗게 빛납니다.
- 범주·블록 아이콘은 글자 기호가 아니라 SVG 로 그립니다(`blockdefs.js` 의 `ICONS`). 글꼴이 없어도 깨지지 않습니다.
- 규칙 점검 줄은 조립소 위에 따로 있어 블록을 가리지 않습니다. 창 최소 크기(1100x720)와 1920x1080 에서 확인했습니다.
- Electron 창에서 열기 → 시작하기 → 결과까지 확인했습니다(2026-11-24, `design/app_electron.png`).
- **블록 자유 배치**: 블록을 조립소 빈 곳에 놓으면 그 자리에 따로 놓입니다(엔트리와 같음). 모자 블록에 붙지 않은 묶음은 실행되지 않고
  조금 흐리게 보입니다. 모자 블록을 끌면 그 묶음 전체가 옮겨집니다. 자리는 저장 파일과 되돌리기에 함께 들어갑니다
  (모델의 `pos`, `loose`). 모자 블록을 옮기지 않았으면 두 묶음은 위아래로 자동 배치됩니다.
- **실행 화면 크게 보기**: 실행 화면 오른쪽 위 버튼을 누르면 블록과 보조 창을 접고 실행 화면만 크게 봅니다(수업 중 함께 볼 때).
- **그래프 탭**: 배우면서 받은 점수, 진자 높이, 모터 힘, 팔이 돌아간 정도 네 개. 이번 시도(파랑 실선)와 지난번 시도(회색 점선)를
  겹쳐 그리고, 마우스를 올리면 그 시각의 값을 보여 줍니다(`js/charts.js`). 규칙이 다르면 점수 크기는 서로 견줄 수 없습니다.

- **디자인 약속** (2026-11-25, `css/app.css` 머리말): 강조색은 파랑 하나(`--accent`), 주황은 모터 힘과 주의, 초록은 통과, 빨강은 실패.
  누르는 것의 모서리는 8px, 카드는 12px. 글자 크기는 20 / 16 / 14 / 13 / 12 / 11.5 여섯 단계만 씁니다.
- **기록 비교**: 기록 표는 시도마다 규칙·시뮬레이션·키트 결과와 모터 힘·팔 움직임을 보여 줍니다. 줄을 누르면 그 시도가 그래프와
  결과 카드의 비교 대상이 됩니다(다시 누르면 풀림). 고르지 않으면 바로 앞 시도와 비교합니다. 최근 8개까지 남깁니다.
- **살펴보기 탭**: ① 미리 배운 에이전트 실행하기(맨 위) ② 키트 부품 네 가지(실행 화면의 번호와 짝) ③ 강화학습의 일곱 가지 말(그림 + 한 줄 풀이).

키트 연결(2026-11-25): 앱이 고친 정책을 키트의 라즈베리파이로 올리고, Pi 가 그 정책을 직접 돌립니다. 아래 '교구 연결' 참고.
키트 맞추기(2026-11-25): 받침 수평은 실행할 때마다 키트가 스스로 재서 진자 영점을 고치고, 팔 마찰·관성과 진자 주기는 연결할 때 확인 단추를 누르면 잽니다.
가짜 키트와 기록 재계산으로만 확인했고 실기 시험은 아직입니다(`kit/README.md`).
아직 안 된 것: 진짜 USB 케이블로 잇는 것(지금은 SSH 로 포트를 끌어와 시험), 잰 값을 앱 시뮬레이션·고쳐 배우기에 넣는 것.

## 물리와 정책은 진짜입니다 (rev11 실기 보정, 2026-11-25)

앱 안의 시뮬레이션은 책상 위 rev11 키트를 재서 맞춘 모델입니다. 파이썬 쪽 기준은 `s2r/s2r_env.py` 이고,
`s2r/export_app.py` 가 상수와 정책을 `src/assets` 로 내보냅니다. 바꾸기 전(rev18b) 자료는 `src_backup_20261124/assets` 에 있습니다.

- **동역학**: rev11 MuJoCo 모델에서 뽑은 질량행렬 계수 + 실기에서 잰 값(팔 축 관성 0.0245 kg·m², 쿨롱 마찰 0.69/0.68 N·m,
  점성 0.17, 결합항 CAD x 0.87, 실제 토크 = 명령 x 0.95, 진자 자유진동 맞춤값).
- **토크 경로**: 실기 호스트(`run_policy.py`)와 같은 순서 — 속도-토크 제한(16 rad/s) → 1.2 A 상한 → 제동 전력 5 W → 0.01 A 양자화, 명령 지연 0~4 ms.
- **관측 6개**: `[cos θ, sin θ, cos α, sin α, θ̇/20, α̇/40]`. 팔 값은 직전 주기의 모터 응답, 진자 각도는 12비트 센서, 진자 속도는 20 ms 차분.
  실기 호스트가 정책에 넣는 값과 같아서, 앱에서 고친 정책을 그대로 키트에 올릴 수 있습니다.
- **안전 정지**: 팔 1100 dps, 진자 25 rad/s 를 넘으면 그 자리에서 끝납니다(실기 호스트가 멈추는 조건).
- **정책**: rev11 보정 환경에서 SAC 로 학습한 64x64 신경망. 아홉 칸 모두 2~5분에 학습됐습니다(`s2r/train_app_rules.py`).
- **학습**: 따라 하기 아홉 칸은 미리 학습한 정책과 그때 기록된 점수 곡선을 씁니다. 블록 규칙은 가운데 칸(약하게, 약하게) 정책에서 출발해
  CEM 으로 고쳐 배웁니다. 기본 설정(24세대 x 20개)이 이 PC 에서 약 9초입니다.
- **조건 섞기**: 고쳐 배울 때 시작 자세 다섯 개를 조건 다섯 개(공칭, 마찰 큼, 마찰 작음, 토크 약함+지연, 결합 약함)와 짝지어 점수를 냅니다.
- **안전 시험 40칸**: 조건 8개 x 시작 5개. 12초 안에 세워 ±5° 안에서 5초 버티면 한 칸 통과, 37칸 이상이어야 실제 키트에 올릴 수 있습니다.
  시작 다섯 개에는 '완전히 매달려 멈춘 상태'가 들어 있습니다(실제 키트의 시작 상태).

### 파이썬 환경과 얼마나 같은가 (`node s2r/check_app_physics.js`)

| 비교 | 결과 |
|---|---|
| 같은 행동 열을 넣었을 때 진자 각도 차이 | 0.5초까지 0.5° 이내, 3초까지 1.6° 이내 |
| 바탕 정책 셋의 128칸 시험 | 파이썬 127 · 121 · 128, 앱 125 · 122 · 128 (같은 칸 124~128/128) |
| 속도 | 제어 스텝 하나 7~11 µs |

### 따라 하기 아홉 칸 (`node s2r/check_app_rules.js`, 앱의 물리로 잰 값)

| | 힘 없음 | 힘 약하게 | 힘 강하게 |
|---|---|---|---|
| **빠르기 없음** | 2.5초 · 안전 39/40 | 2.6초 · 39/40 | 2.4초 · 39/40 |
| **빠르기 약하게** | 2.8초 · 40/40 | 2.4초 · 37/40 | 2.5초 · 40/40 |
| **빠르기 강하게** | 2.8초 · 38/40 | 2.4초 · 40/40 | 2.5초 · 38/40 |

rev18b 모델에서는 "빠르기 강하게 + 힘 아끼기" 두 칸이 못 세웠지만, rev11 보정 환경에서는 아홉 칸 모두 세웁니다(128칸 119~128).
학습지 4쪽의 "아주 강하게 하면?"은 예시 규칙 '힘 아주 아끼기'(안전 시험 탈락)로 볼 수 있습니다.

### 예시 규칙으로 고쳐 배우기 (`node s2r/check_app_learning.js`, 앱 코드 그대로)

- 학습 시간: 규칙마다 약 8~9초 (이 PC)
- 정상 규칙 11개 중 9개가 안전 시험을 통과(128칸 112~128). 나머지 둘은 '개선 없음'(바탕 정책 유지)과 '힘 아주 아끼기'(탈락)입니다.
- 일부러 틀린 규칙 2개는 규칙 점검이 모두 경고하고, 안전 시험도 모두 걸러냅니다.

### 남은 한계

- 시뮬 안전 시험을 통과해도 실기에서 실패할 수 있습니다(2026-11-24 실기: 고친 정책 5개 중 1개가 직립을 지나쳐 계속 돌았음).
  키트 쪽 안전 정지에 '진자가 계속 돌면 정지'가 필요합니다.
- 학습 시간은 이 PC 기준입니다. 학생 노트북에서는 재지 않았습니다.
- 실행 화면의 키트 그림 치수는 예전 그대로입니다(움직임은 rev11, 그림은 개략도).

## 교구 연결 (규약 v2, 2026-11-25)

정책은 **키트 안의 라즈베리파이가 50 Hz 로 직접 돌립니다.** 앱은 가중치를 한 번 올리고(4,673개, 2초 남짓),
실행을 시키고, 키트가 보내 주는 상태로 그림·그래프·판정을 합니다. USB 지연이 제어에 끼어들지 않습니다.

- 규약: `PROTOCOL.md` · 키트 쪽 프로그램과 USB 연결 방법: `kit/README.md`
- 앱 쪽: `src/js/device.js` 의 `KitDevice`. 시뮬레이션(`SimDevice`)과 같은 화면·같은 기록 표를 씁니다.
- 실제 키트 단추는 안전 시험(40칸 중 37칸)과 시뮬레이션 시험을 통과한 정책에서만 눌립니다.
- `키트 상태` 탭의 **키트 점검**은 모터를 움직이지 않고 모터 응답·온도·진자 센서만 읽습니다.
- 키트는 스스로 멈춥니다: 팔 1100 dps, 진자 25 rad/s, 진자가 계속 돎(1.5초에 두 바퀴), 모터 응답 없음, 앱 신호 2초 끊김.
  이 동작은 Pi 쪽에 있고 앱에는 끄는 설정이 없습니다.

키트 없이 눌러 보기(가짜 키트): `kit/README.md` 의 "이 PC 에서 가짜 키트로".

시험한 범위: 모터를 움직이지 않는 시험은 모두 통과했습니다(실기 기록 35개 재생에서 전류 명령 일치, 규약 18항목, Pi 에서 주기 20.00 ms,
앱에서 가짜 키트로 연결→실행→정지→끊김). 실기에서도 앱 → 정책 올리기 → 실행(세움) → 정지 단추까지 확인했습니다(2026-11-25, SSH 로 포트를 끌어옴,
`kit/README.md` 의 실기 표). **진짜 USB 케이블로는 아직 잇지 않았습니다.**
