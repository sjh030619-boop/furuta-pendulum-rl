# 교구 연결 프로토콜 v1 (옛 안, 쓰지 않음)

> 2026-11-25 에 v2(`app/PROTOCOL.md`)로 바꿨습니다. 아래는 바꾸기 전 문서를 그대로 옮겨 둔 것입니다.
> v1 은 앱이 0.02초마다 모터 힘을 보내는 방식이라 USB 지연이 제어 지연이 됩니다.

하드웨어 구성이 아직 확정되지 않았으므로, **전송 수단과 무관한 줄 단위 ASCII 프로토콜**로 정의합니다.
USB CDC 시리얼, TCP, WebSocket 중 무엇을 쓰든 같은 줄을 주고받으면 됩니다. 앱 쪽에서는
`SerialDevice`가 전송 수단만 바꿔 끼우면 되고, 나머지 코드는 건드리지 않습니다.

모든 값은 **정수**입니다. MCU에서 부동소수점 포매팅을 하지 않아도 되게 하려는 것입니다.

## 전송 설정 (시리얼일 때)

- 115200 8N1, 흐름 제어 없음
- 줄 구분자 `\n` (`\r`은 무시)
- 장치는 전원이 들어오면 아무것도 보내지 않습니다. 앱이 `H`를 보낼 때까지 조용합니다.

## 호스트 → 장치

| 줄 | 뜻 |
|---|---|
| `H` | 인사. 장치는 `I`로 답합니다. |
| `E` | 모터 켜기(토크 출력 허용) |
| `D` | 모터 끄기(토크 0, 자유 회전) |
| `Z` | 지금 진자 각도를 "아래로 매달림 = 0"으로 잡기 |
| `U <u>` | 토크 명령. `u`는 −1000 … +1000, 단위는 **τ_max의 1/1000**. τ_max = 1.0 N·m |
| `S` | 상태 스트리밍 시작 (50 Hz) |
| `X` | 스트리밍 중지 |

## 장치 → 호스트

### 인사 응답

```
I <name> <fw> <hz> <tau_mNm>
```

예: `I furuta-rev18b 1.0.0 50 1000`

- `name` 공백 없는 장치 이름 (앱의 장치 목록에 표시)
- `fw` 펌웨어 버전
- `hz` 상태 전송 주기 [Hz]
- `tau_mNm` 이 장치의 τ_max [mN·m]. 앱은 `U`의 눈금을 여기에 맞춥니다.

### 상태 (스트리밍 중, 50 Hz)

```
T <t_ms> <theta_mdeg> <alpha_mdeg> <theta_mdps> <alpha_mdps> <u_applied> <flags>
```

| 항목 | 단위 | 설명 |
|---|---|---|
| `t_ms` | ms | 장치 기준 시각 (랩어라운드 허용, 앱이 차분으로 씀) |
| `theta_mdeg` | 1/1000 ° | 팔 각도 |
| `alpha_mdeg` | 1/1000 ° | 진자 각도. **0 = 아래로 매달림, 180000 = 도립** |
| `theta_mdps` | 1/1000 °/s | 팔 각속도 |
| `alpha_mdps` | 1/1000 °/s | 진자 각속도 |
| `u_applied` | −1000…1000 | 실제로 낸 토크 (속도 포화·안전 제한 반영 후) |
| `flags` | 비트필드 | 아래 참고 |

`flags` 비트: `1` 비상정지, `2` 과속 차단, `4` 엔코더 이상, `8` 모터 통신 이상, `16` 모터 꺼짐.

### 알림

```
! <code> <message...>
```

예: `! overspeed arm 21.4 rad/s`. 앱은 이 줄을 화면 아래 안전 영역에 그대로 보여줍니다.

## 안전 (장치 쪽에서 반드시 구현)

앱이 아니라 **장치가** 지켜야 합니다. 앱이 멈추거나 USB가 빠져도 동작해야 하기 때문입니다.

1. **워치독**: 마지막 `U` 이후 **100 ms** 안에 새 명령이 없으면 토크를 0으로 만듭니다.
2. **팔 속도 제한**: |θ̇| 가 한계를 넘으면 그 방향 토크를 끊고 `flags` 비트 2를 올립니다.
   시뮬레이션은 무부하 속도 16 rad/s의 1차 곡선(`τ ≤ τ_max(1 − |ω|/ω₀)`)을 쓰므로,
   실기도 같은 값으로 맞추면 시뮬과 실기가 가장 가깝게 움직입니다.
3. **진자 속도 제한**: |α̇| 가 한계를 넘으면 토크 0.
4. **비상정지 입력**: 물리 버튼을 받으면 즉시 토크 0, 비트 1을 올리고 `E`가 와도 풀리지 않습니다.
   전원을 다시 넣어야 풀립니다.

> 학습지와 앱 화면에 적힌 "팔이 너무 빨리 돌면 모터가 자동으로 멈춥니다. 이 안전 동작은 끌 수 없습니다"는
> 위 2·3번을 말합니다. 앱에는 이 동작을 끄는 설정이 없습니다.

## 아직 정해지지 않은 것 (당시)

PC와 키트 사이에 무엇이 들어가는지가 미정입니다. 어느 쪽이든 위 줄만 맞추면 앱은 그대로 씁니다.

| 안 | MCU가 하는 일 | 앱 쪽 변경 |
|---|---|---|
| ESP32/Arduino + USB 시리얼 | CAN(RMD-X6-P20) + I2C(AS5600)를 담당, USB CDC로 위 줄 송수신 | 없음 |
| ESP32 + Wi-Fi | 같은 줄을 TCP/WebSocket으로 | `SerialDevice`의 전송 계층만 교체 |
| USB-CAN 직결 | 없음(앱이 CAN 프레임 직접 생성) | `CanDevice` 새로 작성. AS5600 읽을 경로가 따로 필요 |
